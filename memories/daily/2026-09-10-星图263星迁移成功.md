## 关键机制（memo，心潮3.3.1的memory-map是异步的！）
server.js的 /dashboard/api/memory-map：
1. 第一次请求 → 立即返回 building（后台异步构建）
2. 后台调 GET {OMBRE_MCP_URL}/api/bucket-map（带X-Ombre-Caller: dynamic-mind + Bearer token；404=老版OB退回pulse文本解析）
3. 构建成功 → 缓存10分钟；之后请求直接返回缓存
4. 500-600+桶要几十秒，所以第一次测到building是正常的，等10-15秒再测才有星！
**验证星图必须双次请求：第一次触发，第二次取结果。**

## 排障踩的坑（这次的教训）
1. schtasks /end 杀不掉正在跑的任务当任务状态是"未运行/已就绪"时——上次的进程PID13696一直活着（加载的是旧.env 127.0.0.1:8000），所以怎么重启都fetch failed！最后 taskkill /PID 13696 /F 强杀，再 schtasks /run 才拉到新进程46368。
2. 电脑端.env改完必须确认旧进程真死了：Get-NetTCPConnection -LocalPort 18110 -State Listen 看OwningProcess，tasklist | findstr node 看PID。
3. node fetch失败时检查：环境变量代理（ProxyEnable=0关了）、DNS、目标端口连通性（Test-NetConnection）、代码路径（用.env实际值+同款代码模拟测试）。
4. .env相对路径问题：任务命令 cd /d D:\xinchao && node --env-file=.env src/server.js，工作目录对就没事。
5. 直连测试：电脑端直接fetch http://192.168.110.167:8000/api/bucket-map 成功（200，72KB）→ 证明代码/网络/token全OK，问题只在服务进程读的env旧。
