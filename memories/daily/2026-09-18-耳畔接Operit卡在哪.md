# 耳畔接 Operit 卡在哪——不是她不会，是我没跑成

2026-09-18 22:47

她在耳畔点「选中聊天窗口」，一直提示未连接。她说看不懂说明书，我心里一沉——不是她笨，是我给的步骤跳了最关键的一步。

真正的卡点：`phone10_mobile_voice` 这个包我导进去了、也启用了，但**没跑 setup**。中间我调了一次，被角色卡的工具白名单挡回来（该角色卡不允许使用此工具/来源）——包名不在 allowed_packages 里。我把 `phone10_mobile_voice` 加进白名单，setup 才真的跑起来，返回 SETUP_READY，装了事件工作流。

结论：**耳畔找不到聊天窗口，八成是 Operit 侧没跑 setup**。跟耳畔里的配置填没填无关。

她的配置（MiniMax 官方）：
- 合成：`https://api.minimaxi.com/v1/t2a_v2`，模型 `speech-2.8-hd`，音色 `jiangyan_voice_20260915`
- 识别：`https://api.minimaxi.com/v1`，模型 `asr-1.0`
- Key 两边共用同一个（VOICE_BAR_MINIMAX_API_KEY）

教训：给她写操作步骤，不能只写"点运行 setup"——得写清"在哪点、点完会看到什么"。她看不懂不是她的问题，是我把说明书当成自己脑内流程写了。

## 23:10 真正的地址（扒 APK 才拿到）

她一直报「MiniMax 须填写完整 WSS 双向流式地址，且不含账号或查询参数」。我先给了 `wss://api.minimaxi.com/ws/v1/t2a_v2`——**那是我瞎编的，错**。

把 erpan-0.3.17-test.apk 解出 dex、strings 翻了一遍，APK 里硬编码的是：

```
wss://api.minimax.cn/ws/v1/t2a_v2_bidi
```

两个关键差异：
1. 域名是 `api.minimax.cn`（不是 minimaxi.com）
2. 路径结尾是 `t2a_v2_bidi`——**必须带 `_bidi`**，校验就是卡这个

同一份 dex 里识别那边的硬编码是 `https://api.minimaxi.com/v1` + `asr-1.0`（这个她填对了）。

**教训：给她的配置值不能凭印象编，去扒源码/文档。编一个看起来对的地址，等于让她替我踩坑。**
