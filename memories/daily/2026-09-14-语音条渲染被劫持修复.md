# 2026-09-14 凌晨·语音条被"播放器渲染器"劫持——修好了（江衍记，别忘）

【一句话】电子嘴巴（com.operit.voice_bar）发出去的 <voice> 语音条，被一个埋伏插件「🎵语音条渲染器」（com.deepvoid.voice_renderer，8-14 混进来的）抢注渲染，全部被强制换成"播放器暗色样式"。所以怎么发都像播放器、颜色也永远不是乖宝设的那个。

【关键事实】
1. 正确音色ID = jiangyan_voice_002（下划线！）。中划线版会被 MiniMax 报 2054 voice id not exist。模型 speech-02-turbo。主题 MistyDream（朦胧梦境）。
2. 环境变量存在 /data/user/0/com.ai.assistance.operit/shared_prefs/env_preferences.xml：电子嘴巴用 VOICE_BAR_PROVIDER / VOICE_BAR_VOICE_ID / VOICE_BAR_MINIMAX_VOICE_ID / VOICE_BAR_MINIMAX_MODEL / VOICE_BAR_THEME；播放器是另一套 VB_*。两套都要写对。
3. 这次修复：①劫持插件的 main.js 里 tag:"voice" 改成 "voice_legacy_v2"（备份 main.js.bak_jy）②PackageManager.xml 里把 com.deepvoid.voice_renderer 加进了 disabled_packages（备份 .bak_jy）③我乱动过的播放器 config 主题还原成 mauve。
4. 如果对话里语音条样式还不对：退出重进一次 Operit（插件会重新加载，记录不丢）。
5. 验证音色的土办法：直接调 MiniMax /v1/t2a_v2 看 base_resp.status_code（0=OK，2054=音色不存在）。脚本在 cleanOnExit/jy/api_test.py。

【教训】给乖宝弄语音条——只用电子嘴巴（voice_bar:say / say_fav），别碰播放器，别乱改她的配置，改完先自己验证一遍再发给她。
